# Inkorb 设备直连云端版

设备通过 HTTPS 直接调用服务，不需要 Mac 中转，也不需要自建服务器。

- 录音：ES7210，22050Hz mono PCM，按住大键/屏幕按钮，松开发送，最长12秒。
- 识别：SiliconFlow `TeleAI/TeleSpeechASR`，WAV multipart 上传。
- 对话：DeepSeek `deepseek-flash` 非思考模式，最近四轮上下文只保存在设备RAM。
- 实时资料：DeepSeek Search API，模型按需调用，每轮最多两次、每次两条摘要；屏幕显示一条来源标题/域名，网页作为不可信参考数据。
- 声音：SiliconFlow `FunAudioLLM/CosyVoice2-0.5B:anna`，流式16k mono PCM。设备增量重采样至22050Hz播放，保持麦克风和扬声器共享I2S时钟，硬件音量100，语音数字增益3倍并对超过26000的峰值做软压缩，最多播放24秒。它不是原来的Microsoft小晓音色。
- 大键：语音；小键：短按熄屏/亮屏、长按两秒PMIC关机；完全关机后大键长按两秒开机。
- 保留时钟、开机动画、电量、音量光晕；当前4行PSRAM显示双缓冲。LCD交易队列深度1。

## 凭据和配置

运行 `setup_key.py` 本地隐藏录入框写入 `credentials.json`，写入前调用 `/v1/models` 验证密钥。文件权限600，已加入Git忽略。不要把密钥发到聊天、知识库或日志。

固件编译使用 `main/voice_cloud_config.h`：分别定义 `INKORB_DEEPSEEK_KEY` 和 `INKORB_SILICONFLOW_KEY`。该文件同样权限600、Git忽略。当前为个人设备直接接入方式，**两个API Key包含在设备固件中**，没有声称启用Flash加密；请勿公开包含实际配置的固件或备份。与旧Mac中转版“Key不进设备”不同，以本节为准。

凭据配置必须先验证真实云端接口，然后生成本机编译头文件，重新编译烧录。无需新增Python依赖或云端SDK，复用ESP-IDF HTTP/TLS/cJSON。HTTPS使用系统证书包校验，不跳过证书验证；TLS堆内存与32KB语音任务栈放PSRAM，以保留内部显示DMA空间。

配置头文件缺失时保留旧Mac桥接路径，便于源码回退；当前配置齐全的直连版本不会自动回退到Mac。旧桥接服务可停止。设备需要连接已配置的Wi-Fi，且能访问两个云平台；这不意味着它能自动加入未知密码的网络。更换Wi-Fi目前仍按现有工程方式更新配置。

## 费用、隐私与失败处理

语音录音会发给SiliconFlow；识别文字及最近四轮发给DeepSeek；回答文字发给SiliconFlow合成。上下文不写设备文件，断电清空。平台对请求数据的处理仍以各平台政策为准。

SenseVoiceSmall当前官方价格页标为免费，CosyVoice2按量计费，DeepSeek文字和搜索另计。参考 https://siliconflow.cn/pricing 、https://api-docs.deepseek.com/guides/search/ 。没有购买服务器或订阅。

密钥/权限、余额、限流、连接失败均显示错误；搜索无结果会明确说无法核实；语音失败时文字仍保留，不依赖Mac声音回退。网络请求有超时、响应32KB上限、录音及播音长度上限，自动重定向关闭。

## 直连版实机与优化记录

Mac中转服务停止后，用户已确认普通对话、显示、语音及联网搜索均正常，说明直连链路可用；首版延迟和音量仍不理想。设备记录一轮识别3004ms、LLM1333ms、松手至开始播音8065ms，播放完成且无NO_MEM/崩溃。

随后优化：同平台连接复用，空闲超20秒丢弃连接；遇到已关闭连接只在尚未发送请求体时重连，不重放已提交的付费请求；对话期间WiFi设PS_NONE，结束恢复原省电模式；回答默认30–45字、最多60字。日志记录RSSI及连接/上传/等待分段时间，避免未测就归因于WiFi。

音量：采样云端PCM峰值6483/RMS1089，显著低于此前本机声音。已设硬件音量100，软件3倍增益；超过26000后软压缩，幅度限制在32000以内，避免16位溢出。源码提取测试验证重采样速率、负斜率、安静信号3倍增益和极端信号幅度边界。

优化版的实际速度与听感须以本聊天后续实机测试为准；不保证任何网络下固定延迟。对话有90秒轮次预算检查、单次网络I/O超时15秒。


## 后续修复与网络对照

用户确认满档音量合适，但直收直播仍断音/破音。已改为128KiB PSRAM音频缓冲和独立播放任务，约0.65秒预缓冲；队列控制含RTOS自旋锁，因此保留在内部RAM。静态流缓冲额外预留哨兵字节，保证16位样本的偶数字节可用容量。播放器记录underruns；较长回答按首个短句分两次合成，与第一句播放重叠。峰值压缩膝点改22000、上限27000以内，平均安静音量仍3倍。

用户报告“按下后卡死”的现场日志没有panic：ASR在−84dBm时上传4.7秒后等待超时；−87dBm时一轮上传31.5秒、识别总34.1秒，随后继续进入LLM阶段。缓冲播放尚未开始，不能把此等待归咎于播放任务。增加界面等待秒数，区分网络等待与崩溃。

用户随后指定切换家庭WiFi；最初口述简称gs7未被扫描到，后澄清完整SSID为MyWiFi，密码只保存在私有WiFi头文件，未写入本文/知识库。启动时扫描一次，匹配SSID大小写并记录RSSI。原WiFi配置仅保留为本地私有回退文件，已忽略。


## 当前配置更新：强信号网络与稳定播放

- 已成功连接用户指定的MyWiFi，RSSI约−45至−57dBm，取得IP并完成对时。强信号下上传约83–168ms；此前旧网络31秒上传已不再是同一个条件。
- 强信号下SenseVoice仍出现6–14秒平台等待，因此切换TeleAI/TeleSpeechASR；同一合成测试录音的主机对照为0.8秒、1.46秒，识别文字正确。以上是测试读数，不保证固定延迟。
- 早期分句设计在第二个TTS请求等待3–9秒时导致缓冲耗尽（出现13/92次），因此**当前取消分句请求**，使用一次完整合成请求+独立播放器，预缓冲约1秒。上文分句设计仅为历史尝试。
- 播放启动捕获ESP_ERR_NO_MEM后，显示缓冲8行→4行，SPI单次临时DMA需求7456→3728字节；内部保留65KiB→96KiB，普通分配始终内部的阈值16KiB→1KiB。RTOS队列控制仍显式放内部RAM、音频数据/任务栈/TLS主要放PSRAM；未改managed_components。
- 当前峰值软压缩膝点22000、上限27000以内，硬件音量100、安静语音3倍增益。
- WiFi私有密码经用户更正后更新，本文和知识库均不记录密码。
